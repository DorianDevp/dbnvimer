OVERVIEW                                                *dbclient-overview*

DBClient.nvim is a Lua Neovim plugin backed by a Rust executable. The UI is
keyboard-first and stays inside normal Neovim buffers: object tree, query
buffer, result buffer, data buffer, and inspection buffer.

Current adapters support MariaDB, PostgreSQL, and SQLite. The project was built
with AI-assisted rapid development and should be treated as early software until
more real database testing lands.

==============================================================================
SETUP                                                   *dbclient-setup*

>
  {
    "DorianDevp/dbnvimer",
  }
<

DBClient ships a bundled dbclient-core binary in bin/ and uses it by default
when it matches the current OS and CPU architecture.

Bundled binary names:
>
  bin/dbclient-core-linux-x86_64
  bin/dbclient-core-linux-aarch64
  bin/dbclient-core-macos-x86_64
  bin/dbclient-core-macos-aarch64
  bin/dbclient-core-windows-x86_64.exe
<

Configure connections with:
>
  require("dbclient").setup({
    connections = {
      local_mariadb = {
        adapter = "mariadb",
        host = "127.0.0.1",
        port = 3306,
        user = "root",
        password = vim.env.MARIADB_PASSWORD,
        database = "app",
      },
      local_postgres = {
        adapter = "postgres",
        host = "127.0.0.1",
        port = 5432,
        user = "postgres",
        password = vim.env.POSTGRES_PASSWORD,
        database = "app",
      },
      local_sqlite = {
        adapter = "sqlite",
        path = vim.fn.expand("~/data/app.sqlite3"),
      },
    },
  })
<

If your platform does not have a bundled binary yet, build the Rust core:
>
  cargo build --release --manifest-path rust/dbclient-core/Cargo.toml
<

Then set core.command in setup() to the built executable.

==============================================================================
COMMANDS                                                *dbclient-commands*

:DBClient
    Open the DBClient sidebar.

:DBClientConnect {name}
    Select a configured connection.

:DBClientQuery
    Execute selected SQL, or the current statement if no visual selection
    exists.

:DBClientQueryTab
    Open or focus the query buffer.

:DBClientData {schema.table}
    Open a table data preview buffer.

:DBClientClose
    Close active SSH tunnels and clear the selected connection.

KEYS                                                    *dbclient-keys*

Sidebar:
q           Close sidebar.
<CR>        Open the focused item.
o           Open the focused item.
gd          Open data for the focused table.
gs          Inspect the focused schema or table.
gq          Open or focus the query buffer.
]t          Jump to the next visible table.
[t          Jump to the previous visible table.
s           Search visible table names.
n           Repeat the last table-name match.
r           Refresh schema metadata.
e           Open a query buffer.
F           Toggle fullscreen for the current DBClient window.

Query buffers:
<leader>dq  Execute selected SQL or current statement.
<C-CR>      Execute current SQL from normal or insert mode.
F           Toggle fullscreen.

Data buffers:
]c          Move to the next cell.
[c          Move to the previous cell.
]r          Move to the next row.
[r          Move to the previous row.
i           Stage a cell edit in a pending transaction.
I           Edit the current cell and update the database immediately.
E           Edit the current cell and update the database immediately.
T           Review pending transaction changes. Use c to commit, r to rollback,
            or q/Esc to keep editing.
r           Reload the table preview.
F           Toggle fullscreen.

Cell edit popups start empty and show the old value in the popup title. Type
the replacement scalar value and press <CR>. To set SQL NULL, type NULL without
quotes. For date and datetime columns, type the raw value, such as
2025-05-29 or 2025-05-29 00:00:00.

Global:
<leader>dc  Pick a configured connection.

SSH TUNNELS                                             *dbclient-ssh*

MariaDB and PostgreSQL connections may include an `ssh` table. DBClient starts
a local forwarding process before connecting and stops it when the connection
is closed.

>
  ssh = {
    host = "bastion.example.com",
    user = "deploy",
    port = 22,
    identity_file = "~/.ssh/id_ed25519",
    remote_host = "127.0.0.1",
    remote_port = 3306,
    local_host = "127.0.0.1",
    local_port = 0,
  }
<

When `local_port` is 0 or omitted, the Rust core asks the OS for a free port.

==============================================================================
ADAPTER API                                             *dbclient-adapters*

Adapters are Lua modules loaded on demand from `lua/dbclient/adapters`.

Current adapter names:
>
  mariadb
  postgres
  sqlite
<

Each adapter returns:
>
  connect(connection, config) -> handle
  close(handle)
  schemas(handle) -> string[]
  tables(handle, schema) -> table[]
  columns(handle, schema, table) -> table[]
  routines(handle, schema) -> table[]
  preview(handle, schema, table, limit) -> result
  update_cell(handle, schema, table, column, value, pk) -> result
  update_cells(handle, updates) -> result
  query(handle, sql) -> result
<

The UI never imports database-specific modules directly. It asks the adapter
registry for a configured backend, which keeps future adapters lazy.

The Rust core has the same boundary. Its CLI dispatch uses a `DbAdapter` trait,
and database-specific SQL, quoting, and value validation live inside adapter
modules such as `adapters/mariadb.rs`, `adapters/postgres.rs`, and
`adapters/sqlite.rs`.
